# MAZE — решения и устройство

Эзотерический алгоритмический тайловый секвенсер для ESPidi (ESP32-C3, OLED 128×32).
На карте 4×8 рисуются до четырёх маршрутов; указатели идут по ним и играют
ноты из тайлов. Наследует принципы KALEIDOSCOPE и ORCA. Шрифт и дизайн-код — из Калейдоскопа.

Есть прототип в браузере (эталон поведения) и прошивка 0.1 под ESPidi HUB — на железе ещё не проверена.

## Решения по экрану (утверждены)

- Карта 4×8 слева (x 0…64), панель справа (x 66…127).
- Клетка — шаг 8 px: тело тайла 7×7, ряд и столбец 7 — зазор.
- На карте только буквы, эффекты на тайле не показываются. Цельные ноты — заглавные Klaatu с точками,
  диезы — строчные Klaatu без точек (c d f g a; узкие — по центру, хвост g поднят на линию заглавных).
- Октава — полоски в одном ряду, их число — отступ от 5-й (C5 = MIDI 72, как в Калейдоскопе):
  над буквой выше, под буквой ниже; буква сдвигается от полосок на 1 px. Диапазон 2…8.
- Пустая клетка — точка по центру. На маршруте в фокусе к ней добавляется по пикселю туда,
  откуда и куда идёт путь (не больше 3 px). Между соседними клетками маршрута — точка в зазоре.
- Указатель — инверсия клетки, всегда виден, направление не показывается; на ударе ноты вокруг
  него замыкается рамка. Курсор — неоконченная рамка из уголков по 3 px в зазорах.
- Панель: вкладки 1–4, выбранная — инверсией; под каждой — шкала прогресса (растущая шкала
  из прошивки Калейдоскопа) и внизу последний сработавший эффект, в момент срабатывания — инверсией.
  Справа: транспорт и темп; скорость, конец маршрута, MIDI-канал.
- Скорость маршрута — как у Elektron: 1/1 — шестнадцатые, 2/1 — вдвое быстрее … 1/8.
- Конец маршрута: открытый — LOOP, PONG, REV (с конца цепи назад); замкнутый — FWD, REV.
- Коды эффектов — одна буква: A R X P I L (MIDI), O Z V (тайлы), D W T S H (указатель); см. `assets/maze_assets.js`.

## Тайл и эффекты (прототип)

- Тайл: нота, октава, velocity, длина ноты (RT — как у маршрута; по умолчанию у маршрута VEL 100, LEN 50 %),
  один эффект и условие. Нота играет при каждом проходе, условие — только для эффекта.
- Условие проверяется, когда указатель приходит на тайл; эффект действует на этот указатель и его ноту.
  PASS — пришёл; MEET — на тайле уже другой указатель; NEAR — другой указатель на одной из 8 соседних
  клеток; CHNG — соседа сдвинул или повернул эффект, тайл взведён до прихода указателя (ручная правка не взводит).
- MIDI: A арпеджио (аккорд, нот в шаге, направление), R ретчет (2–8, громкость ровно/вверх/вниз),
  X акцент (+8…+64), P афтертач канальный (значение, держать/нарастать/спадать), I интервал (−24…+24),
  L легато (нота до следующего шага).
- Тайлы (со следующего шага, тайл переезжает целиком, за краем — противоположный край):
  O поворот 8 соседей (по/против часовой, 45/90/180°), Z сдвиг ряда (влево/вправо, 1–3), V сдвиг столбца.
- Указатель (держится, пока настройку не изменят): D разворот на месте (LOOP ↔ REV, PONG — сразу,
  замкнутый FWD ↔ REV), W стоп N шагов молча, T стоп N шагов — нота тянется, S скорость на ступень
  быстрее/медленнее, H прыжок (вперёд/назад на N или в начало).
- Правка тайла — кнопка энкодера; PAGE — страницы NOTE → FX → COND; энкодер — значение, TAP+энкодер — параметр.
  С карты — «карта + панель»: шапка панели — NOTE и нота или FX и команда, ниже не больше трёх
  параметров, прокрутки нет; COND — имя страницы и условие. Из маршрута в линию (PAGE) — расширенный вид:
  соседи 3×3, страницы, параметры парами и внизу подсказка как в LSDj (полное имя эффекта или описание
  параметра под курсором, английский — в шрифте нет кириллицы).
- Проверки движка, условий по счёту и проектов: `tests/fx.js` (jsc, см. «Запуск»).

## Условие по счёту (TRG)

- Как условия триггеров у Elektron, один параметр TRG на странице COND, листается энкодером:
  `--` — каждый раз; A:B (1:2 … 8:8) — на A-м из каждых B проходов указателя через тайл;
  PRE — если сработал последний эффект, мимо которого прошёл этот указатель; /PRE — если нет.
- Эффект срабатывает, когда выполнены IF (где) и TRG (когда). Каждый проход считается; если счёт
  не совпал, IF не проверяется (взведённый CHNG ждёт). Счёт и PRE обнуляет только загрузка проекта; пауза их не трогает (иначе тайлы одного маршрута
  после паузы разъезжаются по фазе — так ломалась прогрессия демо 05).
- Под TRG — показ A:B языком карты: квадрат — сработает, точка — пропуск, инверсия — последний проход.
- Пробовали маску проходов (PTN/PSZ Калейдоскопа) — управление курсором и PLAY оказалось неудобным,
  а без модуляции маска не даёт того, что у Калейдоскопа. Вероятность, NEI, FILL и эффект сдвига
  счётчиков пользователь не взял; 1ST не обсуждали.

## Проекты

- 32 слота без имён, вход — TAP+PAGE. TAP+энкодер — слот, энкодер — темп загруженного проекта
  (виден справа внизу; на чужом слоте там записанный темп, энкодер его не трогает). Темп по-прежнему
  меняет и PAGE+энкодер. LOAD — удерживать кнопку энкодера, SAVE — удерживать TAP+кнопку, пока не заполнится шкала. Во время игры загрузка — с начала следующего такта.
- Сохраняется исходник: эффекты O, Z, V двигают только живую карту, LOAD возвращает карту к исходнику.
  Тайлы в обоих слоях — одни и те же объекты, правка тайла попадает и в исходник.
- Автосохранение (через 2 с после правки) — только черновику: слот был пустым при загрузке или уже писался
  автосохранением (AUTO). После ручного SAVE слот защищён (SAVED), «+» в шапке — есть несохранённое.
- Прототип хранит слоты в localStorage браузера (кнопка «очистить слоты»); на железе — LittleFS через
  `mountFiles()` SDK HUB, папка `/maze/`, файл слота около 0,5 КБ с версией и контрольной суммой.

## Бэклог

- **CHNG (важно):** что считать изменением соседа и когда срабатывать. Сейчас — только изменения эффектами,
  тайл взводится и ждёт прихода указателя. Пользователь не уверен, что так и должно быть.
- 1ST / /1ST для TRG — не обсуждали.
- **Оптимизация проигрывания (2026-10-22):** найти, где MIDI-тайминги отстают или идут неровно. Мерить на плате:
  метки времени каждого байта MIDI OUT против ожидаемой сетки (ведущий и ведомый, разные темпы и скорости
  маршрутов), плотные места — ретчет ×8, арпеджио, все 4 маршрута на 2/1, легато и афтертач, сдвиги карты.
  Подозреваемые: блокировка движка на время отрисовки и жестов, задача OLED, очередь UART (31 250 бод —
  3 байта ноты ≈ 1 мс, в плотный шаг может не влезть), сглаживание внешнего клока, отложенные note-off.
- Рандомизация проектов — не обсуждали, что именно случайно (ноты, эффекты, маршруты) и каким жестом.
- Демо-проекты, часть 2: запуски маршрутов, TRIG, лад — после этих механик. Часть 1 сделана (0.3, см. «Демо-проекты»).
- **Запуск маршрута указателем (серьёзная переделка, заменяет «связь маршрутов» EOC → LNK):** когда указатель
  одного маршрута проходит через начальную или конечную клетку другого, у второго маршрута запускается ещё один
  указатель. Так получаются сложные триггерные пульсации. Ответы пользователя (2026-10-22):
  - запускает любой указатель (и основной, и запущенный), при каждом проходе, без условий;
  - вход в начальную клетку B — новый указатель с начала вперёд, в конечную — с конца назад;
  - запуск сразу, на этом же шаге;
  - запущенный указатель — one-shot: проходит маршрут и исчезает;
  - на маршруте до 8 указателей; в настройках маршрута — свой предел (защита от разгона цепочек A → B → A);
  - вид — как у основного указателя;
  - режим маршрута TRIG (принят): свой указатель стоит, звучат только запущенные;
  - встречные указатели на одной линии уничтожаются при встрече, MEET на это не срабатывает:
    основной указатель не гибнет никогда (при встрече с ним гибнет запущенный), два запущенных гибнут оба;
  - встреча — и в одной клетке, и когда указатели проскочили друг мимо друга в зазоре;
  - нота в клетке встречи играет, указатели гибнут после неё;
  - указатель на стопе (W, T) тоже участвует во встрече.

## Лад (скейл-энжин, 0.4)

- Тоника и лад — у проекта. Лады как в Trajectories (MAJ MIN DOR PHR LYD MIX LOC HMIN MMIN) плюс PMAJ, PMIN
  и CHRM — лад выключен, всё как раньше. Старые проекты и демо — CHRM.
- Тайл хранит ноту как записали. На карте, в правке и в звуке — ближайшая нота лада (при равенстве нижняя),
  поэтому от смены лада туда-обратно ноты не уползают. Новые ноты — только из лада: KEY листает ноты лада,
  правка записывает в тайл то, что видно.
- I в ладу — ступенями. A в ладу — аккорды ступенями: интервал переводится в ступени как round(h·ступеней/24),
  h — полутоны ×2, терция — 3,5 полутона, поэтому MAJ и MIN дают одно трезвучие лада (решение пользователя);
  в пентатонике выходят её «трезвучия» (A PMIN: A C E).
- Настройка — на экране проектов справа: тоника и лад в строке LOAD, темп внизу. Энкодер правит выбранное
  (в плашке), TAP+PAGE — следующее поле (тоника → лад → IN → темп), TAP+энкодер — слот. Пока держишь LOAD или
  видна OK/BAR, тоника и лад скрыты под шкалой. Чужой слот — записанные значения тонким.
- Формат проекта — версия 2 (+ лад и тоника перед CRC, 425 байт); версия 1 читается как CHRM.

## Транспонирование фразы (0.5)

- Две команды, обе — про всю фразу, а не про ноту тайла. **K** (KEY CHANGE) — новая тоника, с начала следующего
  такта; фраза переезжает в ближайшую сторону (−6…+5 полутонов от тоники проекта), сдвиг M сбрасывается.
  **M** (MOVE IN SCALE) — сдвиг на N ступеней лада (−7…+7) сразу, копится по кругу внутри октавы (в CHRM — полутоны).
- Это игра, а не проект: не сохраняется, сбрасывается при старте (продолжении после паузы) и загрузке. Карта показывает записанную фразу.
- Кого двигать — настройка маршрута KEY ON/OFF (по умолчанию ON; в проекте — бит 1 байта «замкнут»).
- После смены тональности в панели вместо скорости маршрута на 600 мс — звучащая тоника в плашке.
- Настройки маршрута — теперь две колонки: SPD END / CH VEL / LEN KEY.
- Демо 05 POINTER (лад E MIN): кольцо из 8 клеток на 1/8, круг ровно 4 такта. M +3 (2:4) на клетке старта,
  K B (2:4) и K E (3:4) на двух последних — они ждут такта и попадают на начало круга. Выходит E → A → B → E.

## Транспонирование с MIDI IN (0.6)

- Нота с MIDI IN работает как K, но сразу (со следующего шага маршрутов), защёлкой (отпустил — тональность
  осталась), с октавами: дом — тоника проекта в 4-й октаве (C4 = 60), выше клавиша — выше фраза.
  Из зажатых берётся нижняя. Сбрасывает сдвиг M и ждущий K; дальше кто последний — тот и прав.
- Как K: сбрасывается при старте, KEY OFF у маршрута учитывается, вспышка звучащей тоники в панели.
- Вход — поле IN на экране проектов в строке SAVE: OFF, ALL, 01–16; по умолчанию OFF. Это настройка устройства,
  а не проекта (`/maze/config`), поэтому на чужом слоте не тонкая. Поля по TAP+PAGE: тоника → лад → IN → темп.
- Разбор MIDI IN — в ядре (`MidiIn`: running status, note on с нулевой velocity — отпускание, системные мимо),
  проверяется на компьютере. В прототипе — клавиши на октаву под экраном и настоящая клавиатура через Web MIDI.

## Демо-проекты

- Пять демо в слотах 01–05, источник — `assets/demos.json`; `tools/gen_demos.py` делает из него `MAZE/maze_demos.h`
  и `assets/maze_demos.js`, так что прошивка и прототип играют одно и то же (сцены demo_02…05 сверяются попиксельно).
- Заливать отдельно нельзя — демо идут с прошивкой. При старте, если версия демо (`version` в json, на флеше —
  `/maze/demos`) другая, демо пишутся в слоты 01–05 с признаком «демо» (бит 1 байта флагов слота): в пустые
  и поверх прежнего демо. Ручной SAVE признак снимает — такой слот следующая версия не трогает. До версии демо 3
  признака не было, поэтому при переходе на 3 обновляются все 01–05 (просьба пользователя, 0.7).
  На чистой плате открывается 01.
- 01 MIX — всего понемногу (прежнее единственное демо, байт в байт). 02 MIDI — эффекты ноты A R X P I L.
  03 MAP — O, Z, V переписывают карту. 04 COND — MEET, NEAR, CHNG, TRG 1:2 / 3:4 / PRE.
  05 POINTER — S, D, W, T, H, PONG и REV, прогрессия K и M (с версии демо 2).
- Новое демо или правка — меняешь json, поднимаешь `version`, `python3 tools/gen_demos.py`.

## Синхронизация

- Клок на MIDI IN — MAZE автоматически ведомый (в панели EXT вместо темпа); нет клока — ведущий.
- В ведомом режиме снятие паузы квантуется к ближайшему новому шагу внешнего клока (6 тиков из 24 на четверть).
  Stop с MIDI IN — пауза, Start и Continue — как TAP+TAP. Темп с PAGE+энкодер у ведомого не меняется.
- Ноты с MIDI IN не звучат — единственное исключение: транспонирование фразы (см. ниже).
- В прототипе клок имитируется: галочка «клок на MIDI IN», темп и кнопки Start / Stop / Continue.

## Стирание и мьют

- Кнопка энкодера на карте и в линии срабатывает по отпусканию. Удержание (шкала заполняется) стирает
  то, что в фокусе: на карте — тайл (нота, эффект, условия, VEL/LEN), в линии — цепь маршрута, тайлы остаются.
  Очищать всю карту отдельно не нужно — LOAD пустого слота даёт новый проект.
- PLAY по отпусканию — следующий маршрут; удержание PLAY — мьют маршрута в фокусе. Заглушённый маршрут
  молчит, но указатель идёт и эффекты срабатывают. Вид: цифра вкладки зачёркнута, шкала пунктиром,
  указатель — шахматка вместо инверсии; в линии вместо канала — MUTE. Мьют в проект не сохраняется.

## Прошивка

- Перенос прототипа один в один: те же сцены рисуются C++-кодом и сравниваются с JS попиксельно (`tests/host/compare.py`).
- Время — тики 24 PPQN: на шаг 3 (2/1), 6 (1/1), 12 (1/2), 24 (1/4), 48 (1/8); такт — 96 тиков.
  Ведущий считает тики сам и шлёт 0xF8 наружу, ведомый идёт по 0xF8 с входа; 500 мс без клока — снова ведущий.
- Движок — задача на esp_timer каждые 500 мкс; кадр OLED уходит в отдельной задаче, как в RED SEA. MIDI — очередь с отложенными note-off;
  легато снимает предыдущую ноту после новой, афтертач — канальный (0xD0).
- Проекты — LittleFS через `mountFiles()` SDK: `/maze/slotNN.bin` (байт флагов + проект 425 байт с CRC32, версия 2),
  `/maze/current` — последний слот. Запись — вне блокировки движка, через `.tmp` и переименование.
- Демо-проекты идут с прошивкой, см. «Демо-проекты».
- Собирать только с `FlashMode=dio`. Загрузчик HUB работает в DIO, и прошивка в QIO читает флеш
  мусором (`esp_flash_read`): LittleFS не монтируется, а при каждом старте раздел заново размечается.
  На старте в USB-консоль уходит строка `MAZE: files mounted, /maze ok`; если флеш не смонтирован,
  в шапке экрана проектов — NOFS.
- Энкодер — ENC_A 5, ENC_B 6, 4 отсчёта на щелчок; кнопки — пины из SDK.

## Запуск

```
python3 tools/build_proto.py      # → proto/dist/maze_proto.html
python3 tools/render_screens.py   # → screens/
jsc tools/screens/stub.js assets/font/kaleidoscope_font.js assets/maze_assets.js assets/maze_demos.js proto/maze.js tests/fx.js
```

Прошивка (из папки проекта):

```
g++ -std=gnu++17 -O1 -Wall tests/host/engine.cpp MAZE/maze_core.cpp MAZE/maze_ui.cpp -o /tmp/maze_engine && /tmp/maze_engine
python3 tests/host/compare.py
python3 tools/gen_assets.py       # → MAZE/maze_assets.h
python3 tools/gen_demos.py        # → MAZE/maze_demos.h, assets/maze_demos.js
python3 tools/make_cover.py       # → cover.png; затем espidi_hub.py cover cover.png > MAZE/cover.h
arduino-cli compile --fqbn esp32:esp32:esp32c3:PartitionScheme=huge_app,FlashMode=dio --output-dir build MAZE
python3 ../ESPidi-HUB/tools/espidi_hub.py repo . --build build/MAZE.ino.bin --publish
```

`jsc` — /System/Library/Frameworks/JavaScriptCore.framework/Versions/Current/Helpers/jsc.
